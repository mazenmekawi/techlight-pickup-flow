TechLight Flow — data and operational boundaries
=================================================
TechPro login and tracking tokens use the existing Android Keystore encrypted Session implementation. Never include credentials in diagnostics.
The local receiver does not log into TechPro. It receives only redacted display identifiers (phone suffix, invoice or delivery number), provider display information, screen configuration, and ETA summary. Full phone numbers, customer names, kitchen notes, line items and TechPro tokens are not sent in display snapshots.
QR includes a private pairing secret. Treat it as confidential; unused QR validity is five minutes. Transport uses per-connection challenge and AES-GCM authenticated frames. Persistence of highest snapshot sequence prevents an older snapshot restoring a removed number. This is a functional security review and regression test, not a formal penetration-test certification.
The receiver reports whether its Activity is foreground, and acknowledges only after UI rendering logic succeeds. That acknowledgement is not proof of visibility on a physical monitor or success on TechPro.
Defaults in Flow: auto publish ready=true, permit LAN display while TechPro synchronization is pending=true. These defaults intentionally support the kitchen-led workflow. A separate strict mode waits for server confirmation. Pending server status is never relabelled as synchronized because a customer display acknowledged it.
Delivered is terminal locally. Stale snapshots and later details do not reopen it. New additions to a merely ready order still return it to preparation. Late changes on a delivered order are retained for later investigation, not automatically announced to a public screen.
Local cleanup persists identity-based tombstones; it never calls invoice deletion or sends a handover operation. Undo is limited to the last cleanup and does not automatically republish public identifiers. Historical terminal identity records are retained to avoid re-import; this version does not erase them automatically as a storage optimization.
Manual delivery cards are display records, not invoices or integrations with third-party delivery apps.
The Flow application IDs differ from the prior release because the previous signing private key is unavailable. Old app private storage is not read or migrated automatically. Signing material, SDK binaries, external font files and real account data are excluded from the source handoff.
No real TechPro account was used in verification. API permissions, all actual response shapes, physical LAN reachability, device camera/audio, prolonged operation and all Android versions have not been verified.
